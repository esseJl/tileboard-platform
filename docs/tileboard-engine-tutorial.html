🚀 شروع: این آموزش چیست و چطور از آن استفاده کنیم؟

نقشه‌ی راه کامل یادگیری موتور — از صفر تا ساخت و اجرای یک بازی واقعی روی برد LED.

🎯 این آموزش چه چیزی را پوشش می‌دهد؟

  • معماری موتور: لایه‌های Game → GameContext → GameEngineImpl → GameSessionImpl → BoardChannel → TileGatewayClient
  • هر ۱۴ انیمیشن نام‌دار (countdown×2, win×4, lose×4, standby×4) با رفتار دقیق فریم‌به‌فریم، زمان‌بندی و API جاوا
  • سیستم Shape کامل: ۵ نوع شکل، ۲ استایل، ۵ مسیر حرکت، ۴ سرعت، trail، pulse، کامپوزیت و presetهای JumpGameAnimations
  • آموزش گام‌به‌گام ساخت بازی مشابه SequentialTouchGame + ثبت در Spring
  • best-practice و ضدالگوها + نکات هم‌روندی (Thread-Safety) استخراج‌شده از خود سورس

🧭 مسیر پیشنهادی مطالعه

  1. بخش‌های معماری → مفاهیم → چرخه‌ی حیات را بخوانید (۳۰ دقیقه)
  2. وارد شبیه‌ساز ۱ شوید و هر ۱۴ انیمیشن را اجرا کنید؛ کد جاوای معادل هرکدام را ببینید
  3. بخش سیستم Shape را بخوانید و در شبیه‌ساز ۲ شکل/مسیر/سرعت‌های مختلف را ترکیب کنید
  4. بخش ساخت بازی گام‌به‌گام را پیاده کنید و با تست سخت‌افزاری روی برد واقعی اجرا بگیرید
هر دو شبیه‌ساز، منطق کلاس‌های جاوا را فریم‌به‌فریم و با همان زمان‌بندی (pause/sleep میلی‌ثانیه‌ای) بازتولید می‌کنند؛ چیزی که روی LED مجازی می‌بینید دقیقاً همان چیزی است که روی سخت‌افزار واقعی نمایش داده می‌شود.

🏗️ معماری کلی موتور

بازی شما فقط با دو چیز حرف می‌زند: GameContext و فیچرها. بقیه را موتور مدیریت می‌کند.

┌──────────────────────────────────────────────────────────────────┐ │ Game (your code) │ │ implements GameLifecycle { onStart, onTileEvent, onTick, onStop }│ ├──────────────────────────────────────────────────────────────────┤ │ GameContext (passed to every lifecycle method) │ │ ├─ BoardContext: publishBoard / setTile / fillBoard / newBoard │ │ ├─ SessionControl: winSession / loseSession / stopSession / state│ │ ├─ FeatureProvider (14 features: scores, timer, animations, ...)│ │ └─ eventBus() │ ├──────────────────────────────────────────────────────────────────┤ │ GameEngineImpl │ │ ├─ GameRegistry (register / instantiate games) │ │ ├─ activeSessions: ConcurrentHashMap<sessionId, GameSessionImpl> │ │ ├─ exclusiveSessionId: AtomicReference (one session owns board) │ │ └─ TouchFrameRouter + EngineFrameRouter (frame -> TileEvent) │ ├──────────────────────────────────────────────────────────────────┤ │ GameSessionImpl (one instance per running game) │ │ ├─ BoardChannel (ReentrantLock + gatewayWriteLock) │ │ ├─ FeatureBundle (fresh Score/Health/Animation... per session) │ │ ├─ GameState (synchronized HashMap for YOUR session data) │ │ └─ SessionLifecycle (CAS state machine: IDLE->RUNNING->FINISHED)│ ├──────────────────────────────────────────────────────────────────┤ │ TileGatewayClient (serial-protocol) -> SerialTransport -> HW │ └──────────────────────────────────────────────────────────────────┘
کلاس بازی شما Singleton است! وقتی با registry.register(game) ثبت می‌کنید، یک نمونه بین همه‌ی سشن‌های آینده مشترک است (مثل مدل Servlet). پس هیچ state قابل‌تغییرِ سطح سشن را در فیلد نمونه نگه ندارید — همه‌چیز باید در ctx.state() یا آبجکت‌های فیچر (که هر سشن تازه ساخته می‌شوند) ذخیره شود. اگر واقعاً به state سطح نمونه نیاز دارید، با register(descriptor, factory) ثبت کنید تا هر سشن یک نمونه‌ی تازه بگیرد.
قانون طلایی: هر چیزی که با شروع سشن جدید باید «ریست» شود → داخل ctx.state(). هر چیزی که ثابت و مشترک است (descriptor، palette، ثابت‌ها) → فیلد static final. به همین سادگی.

جریان داده‌ی یک لمس (Touch Flow)

  1. سخت‌افزار فریم DATA_IN می‌فرستد → TileGatewayClient دریافت می‌کند
  2. EngineFrameRouter فریم‌های چندتکه را سرهم می‌کند → Board<Boolean>
  3. TouchFrameRouter به سشن مالک انحصاری برد مسیریابی می‌کند
  4. GameSessionImpl.handleTileEvent تاریخچه و سرعت واکنش را ثبت می‌کند، بعد game.onTileEvent را صدا می‌زند (فقط وقتی سشن RUNNING است؛ هم TOUCH و هم RELEASE تحویل داده می‌شوند)

📚 مفاهیم پایه: Game ،Descriptor ،Lifecycle ،Context

چهار اینترفیسی که ۹۰٪ کار روزمره‌ی شما با موتور است.

۱) ‎GameDescriptor — شناسنامه‌ی بازی

// متادیتای ثابت بازی: شناسه، نام، ابعاد برد لازم، تعداد بازیکن
GameDescriptor desc = GameDescriptor.builder("sequential-touch", "Sequential Touch Challenge")
    .category("TUTORIAL")
    .description("Tiles light up sequentially; touch to score.")
    .boardSize(8, 8)        // باید با DeviceConfiguration برابر باشد، وگرنه GameSessionException
    .players(1, 1)           // min=1, max=1 (پیش‌فرض 1..1 و برد 8x8)
    .build();

۲) ‎GameLifecycle — چهار نقطه‌ی هوک موتور

public interface GameLifecycle {
    void onStart(GameContext ctx);                  // یک‌بار در شروع سشن (روی نخ صداکننده‌ی startGame)
    void onTileEvent(GameContext ctx, TileEvent e); // هر لمس، فقط وقتی RUNNING (روی نخ callback گیت‌وی)
    default void onTick(GameContext ctx) {}           // هر tick موتور (قابل‌تنظیم در Properties)
    default void onStop(GameContext ctx, GameResult r) {} // پایان (win/lose/stop): برد را خاموش + منابع را آزاد کن
    default void onError(GameContext ctx, Throwable t) { ctx.stopSession(); }
}
متد onTileEvent روی نخ callback گیت‌وی سریال اجرا می‌شود؛ پس باید سبک و سریع باشد. کار سنگین (انیمیشن طولانی، .join()، sleep) را داخل آن انجام ندهید — به‌جایش state را به‌روز کنید و ادامه را به onTick یا CompletableFuture.thenRun بسپارید.

🔄 چرخه‌ی حیات سشن و مدل هم‌روندی

بدانید هر متد روی کدام نخ اجرا می‌شود و هر قفل از چه چیزی محافظت می‌کند.

ماشین حالت سشن (CAS — دقیقاً یک‌بار)

IDLE -> STARTING -> RUNNING -> FINISHING -> FINISHED \-> CANCELLED (on early failure) finishSession(): compareAndSet guarantees win/lose/stop run EXACTLY once, even under races.
  • winSession(winners) / loseSession() / stopSession() همگی به finishSession می‌رسند و فقط یکی برنده می‌شود
  • بعد از پایان، موتور game.onStop(ctx, result) را صدا می‌زند و برد را آزاد می‌کند (STOP/SET روی سیم)

نقشه‌ی نخ‌ها و قفل‌ها

کامپوننتمکانیزم
BoardChannelReentrantLock برای بافر + gatewayWriteLock برای سیم؛ معنای coalescing: همیشه تازه‌ترین برد ارسال می‌شود، نه لزوماً بردی که شما ساختید
AnimationSystemSingleThreadExecutor + نسل AtomicLong؛ هر انیمیشن جدید، قبلی را cooperative کنسل می‌کند
GameStatesynchronized HashMap؛ put/get/getOrDefault/clear
ScoreSystemConcurrentHashMap<String, AtomicInteger>
GameTimerAtomicReference<Runnable> برای onExpire؛ چک انقضا هر tick

الگوی استاندارد پایان بازی: اول انیمیشن برد/باخت را غیربلاکینگ پخش کنید و داخل thenRun سشن را تمام کنید تا بازیکن انیمیشن را کامل ببیند: ctx.animations().playWinAnimation(RADIAL_BURST).thenRun(() -> ctx.winSession(ctx.players())); هرگز روی نخ گیت‌وی join()/get() نکنید.

// ساخت، دست‌کاری و انتشار برد (row اول، col دوم!)
Board<TileColor> b = new Board<>(width, height, TileColor.OFF);
b.set(row, col, TileColor.RED);

BoardChannel فریم‌های تکراری پشت‌سرهم را اصلاً روی سیم نمی‌فرستد (lastSentBoard) و اگر دو نخ هم‌زمان بنویسند، تازه‌ترین اسنپ‌شات ارسال می‌شود. پس با خیال راحت از چند نخ بنویسید.
Position(row, col) مختصات منفی را نمی‌پذیرد و IllegalArgumentException می‌دهد. شکل‌هایی که لبه‌ی برد را لمس می‌کنند (یا مسیرهای پرشی که بالای سطر ۰ می‌روند) در معرض کرش‌اند — جزئیات و راه‌حل در بخش shape.

🎬 شبیه‌ساز ۱ — انیمیشن‌های win / lose / standby / countdown

هر ۱۴ انیمیشن نام‌دار موتور را روی LED مجازی اجرا کنید. روی هر دکمه که بزنید، توضیح رفتار + کد جاوای معادل آن نمایش داده می‌شود. انیمیشن‌های standby بی‌نهایت حلقه می‌زنند (درست مثل جاوا) و فقط با «توقف» یا اجرای یک انیمیشن دیگر قطع می‌شوند — دقیقاً همان رفتار cancelCurrent().

⚙️ تنظیمات برد

🏆 WIN — یک‌بار اجرا و پایان (thenRun → winSession)
💀 LOSE — یک‌بار اجرا و پایان (thenRun → loseSession)
💤 STANDBY — حلقه‌ی بی‌نهایت تا کنسل شدن
⏱️ COUNTDOWN — انتخاب خودکار simple/scalable از روی ابعاد
وضعیت: آماده کلید: — فریم: 0

API موتور انیمیشن (AnimationSystem) — قلب تپنده‌ی نمایش

// دسترسی از داخل بازی:
AnimationSystem anim = ctx.animations();

// --- API سطح بالا (پیشنهادی برای شروع) ---
anim.playCountdown(1000);                                   // انتخاب خودکار simple/scalable
anim.playWinAnimation(WinAnimationType.FIREWORKS);        // پیش‌فرض: RADIAL_BURST
anim.playLoseAnimation(LoseAnimationType.PULSE_RED);      // پیش‌فرض: FADE_TO_RED
anim.playStandbyAnimation(StandbyAnimationType.BREATHING); // ♾️ تا cancelCurrent()

// --- API کلیدی (دقیق + قابل‌توسعه) ---
anim.play("win.fireworks");                          // با کلید رجیستری
anim.play("countdown.scalable", Map.of("digitDurationMs", 700L));
anim.registerAnimation("my.effect", (token, ctx2) -> { ... }); // انیمیشن سفارشی خودت!
anim.play(myAdHocAnimation);                          // اجرای بدون ثبت (مثل shapeهای داینامیک)
anim.cancelCurrent();                                   // قطع فوری انیمیشن جاری

// --- الگوی برد/باخت: انیمیشن کامل دیده شود، بعد سشن تمام شود ---
anim.playWinAnimation(RADIAL_BURST).thenRun(() -> ctx.winSession(ctx.players()));

// --- الگوی standby محدود (چون بی‌نهایت است، با تایم‌اوت get و بعد کنسل): ---
try { anim.playStandbyAnimation(BREATHING).get(2, TimeUnit.SECONDS); }
catch (Exception e) { anim.cancelCurrent(); }  // ⚠️ هرگز این get را روی نخ گیت‌وی (داخل onTileEvent) صدا نزن!
هر play یک CompletableFuture<Void> برمی‌گرداند: با موفقیت complete، با کنسل‌شدن cancel، و با خطا exceptionally می‌شود. انیمیشن بعدی خودکار قبلی را کنسل می‌کند (نسل generation++) — پس لازم نیست قبل از هر play دستی کنسل کنید.
انیمیشن سفارشی = یک لامبدا/کلاس BoardAnimation با امضای run(token, ctx). داخل حلقه فقط از token.show(board)، token.pause(ms) (پرتاب‌کننده‌ی اکسپشن کنسلی) یا token.sleep(ms) (برگرداننده‌ی boolean) استفاده کنید تا cooperative cancellation درست کار کند. ctx.width/height/rng/param هم در اختیارتان است.

public void onStart(GameContext ctx) {
    ctx.fillBoard(TileColor.OFF);
    ctx.scores().resetAll();
    ctx.state().clear();

    // ۲ ثانیه standby (بی‌نهایت است → با get تایم‌دار + کنسل مهارش کن)

        ctx.animations().playStandbyAnimation(BREATHING).get(2, TimeUnit.SECONDS);
    } catch (Exception e) { ctx.animations().cancelCurrent(); }

    ctx.animations().playCountdown(1000).join();  // 3→2→1→چشمک؛ join چون onStart روی نخ امن است

    // ذخیره‌ی state سشن (نه فیلد نمونه!)
    List<Position> all = ...; // همه‌ی تایل‌ها row-major
    ctx.state().put("positions", all);
    ctx.state().put("index", 0);

    ctx.timer().startCountdown(Duration.ofSeconds(90), () ->
        ctx.animations().playLoseAnimation(DESCENDING_CURTAIN)
           .thenRun(() -> ctx.loseSession()));

گام ۳ — onTileEvent: لمس درست/غلط (سبک و سریع!)

public void onTileEvent(GameContext ctx, TileEvent e) {
    if (e.type() != TileEventType.TOUCH && e.type() != TileEventType.HOLD) return;
    List<Position> positions = ctx.state().get("positions", List.class).orElse(List.of());
    int i = ctx.state().getOrDefault("index", Integer.class, 0);
    if (positions.isEmpty() || i >= positions.size()) return;

    if (e.position().equals(positions.get(i))) {
        String pid = ctx.players().get(0).id();
        ctx.scores().add(pid, 10);                        // اتمیک
        Position done = positions.get(i);
        ctx.setTile(done.row(), done.col(), TileColor.OFF);
        ctx.state().put("index", i + 1);
        if (i + 1 >= positions.size()) {             // برد!
            ctx.timer().stop();
            ctx.animations().playWinAnimation(RADIAL_BURST)
               .thenRun(() -> ctx.winSession(ctx.players()));
        } else lightCurrentTile(ctx);
    } else {                                            // لمس غلط: فلش باخت کوتاه + روشن‌کردن مجدد
        ctx.animations().playLoseAnimation(FADE_TO_RED)
           .thenRun(() -> lightCurrentTile(ctx));
    }
}

public void onStop(GameContext ctx, GameResult result) {

    catch (Exception ignored) {}

}

}

💎 best-practiceها، ضدالگوها و یافته‌های بررسی سورس

چک‌لیست کیفیت قبل از تحویل هر بازی + دو یافته‌ی مهم از بازبینی دقیق کد موتور.

✅ همیشه انجام بده

  • state سشن → فقط ctx.state()؛ ثابت‌ها → static final
  • پایان سشن → داخل thenRun بعد از اتمام انیمیشن برد/باخت
  • onTileEvent سبک؛ بدون join/get/sleep (نخ گیت‌وی!)
  • در onStop برد را خاموش و انیمیشن را کنسل کن (best-effort با try/catch)
  • ابعاد descriptor = ابعاد DeviceConfiguration
  • برای صحنه‌های چندموجودیتی از CompositeShapeAnimation استفاده کن (یک اسلات!)
  • سرعت‌ها را با AnimationSpeed (سلول/ثانیه) بده نه تأخیر دستی — مستقل از ابعاد برد می‌مانی

⛔ هرگز انجام نده

  • فیلد قابل‌تغییر در کلاس Game (نشتی state بین سشن‌ها!)
  • new Thread / while(true) دستی داخل بازی — از onTick و GameTimer استفاده کن
  • فرض اینکه publish دقیقاً همان بافر تو را فرستاده (coalescing!)
  • فراخوانی Thread.sleep روی نخ گیت‌وی/انیمیشن — فقط token.pause/sleep
  • انتشار برد از داخل BoardAnimation با publisher مستقیم، وقتی token.show لازم است (کنسل‌شدن را دور می‌زند)
  • نقطه/شکل روی لبه بدون حاشیه‌ی امن (یافته‌ی ۱ 👇)

🔍 یافته‌ی ۱ (مهم): Position منفی = اکسپشن — مراقب لبه‌ها باش

رکورد Position در سازنده مختصات منفی را رد می‌کند، اما ShapeRasterizer و Trajectories قبل از ساخت Position گارد ندارند. نتیجه: اگر شکل به لبه بچسبد (مثلاً touchRipple روی تایل (0,0) با شعاع ۳) یا اوج jumpArc بالای سطر ۰ برود، IllegalArgumentException پرتاب و Future انیمیشن exceptionally تمام می‌شود. راه‌حل فعلی: حاشیه‌ی امن (ارتفاع پرش ≤ فاصله‌ی مبدأ تا لبه، مرکز پالس ≥ maxRadius از لبه‌ها) + گرفتن خطا روی Future. راه‌حل ریشه‌ای پیشنهادی برای تیم موتور: گارد try/catch یا بررسی کران در rasterize و at(t)، یا متد clamp در Position.

🔍 یافته‌ی ۲ (جزئی): جابه‌جایی سطر/ستون در شمارش معکوس مقیاس‌پذیر

در ScalableCountdownAnimation.renderDigit فراخوانی به‌صورت board.set(x, y, color) انجام شده، در حالی‌که قرارداد Board.set(row, col) است و x در آن کد نقش ستون را دارد. روی بردهای مربع (۸×۸) ارقام درست دیده می‌شوند، ولی روی بردهای غیرمربع رقم وارونه/جابه‌جا می‌شود. اصلاح پیشنهادی یک‌خطی: board.set(y, x, color). (شبیه‌ساز ۱ رفتار صحیح را نشان می‌دهد.) همچنین ناسازگاری کوچک: رنگ رقم ۲ در این کلاس BLUE ولی در متد قدیمی BoardEffects.renderDigit برابر YELLOW است.
